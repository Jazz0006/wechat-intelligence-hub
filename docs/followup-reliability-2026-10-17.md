# 跟进判断与去重修复

本轮只修改情报库的本地分析、消息去重和联系人报告，不改变微信读取、密钥获取或发送权限。

## 修复内容

1. `hybrid` 联系人日报收录未打标签、尚未回复的首次商业询问。普通品牌资讯不因此进入待回复列表。`priority_labels_only` 仍按用户选择限制范围。
2. 对方明确取消当轮交付后，不再把对应旧稿列为待兑现。仅影响报告推断，不自动修改人工商机状态。
3. 承诺按会话、明确项目、轮次和交付物保守匹配。其他项目的完成消息不能解除当前项目义务；多个未完成承诺同时保留。模糊、否定、条件式和未来计划不作为完成证明。
4. 消息哈希及内存去重加入 reader 会话 ID；搜索结果保留可用的 talker。旧哈希在再次同步同一已确认会话时惰性升级，保留消息 ID、FTS、链接和商机证据引用。未知来源不猜测合并。
5. 联系人报告新增 `商机列表`、`待兑现承诺`，逐项展示阶段、下一步和跟进日期。旧 `商机`、`历史承诺` 字段保留兼容，但不再用于代表完整列表。

## 升级边界

- 更新代码后需要重新生成报告；已有 Markdown/HTML 不会自动变化。
- 旧版本因同名去重丢失的记录，需要重新读取对应会话才能补回；本次不删除或重建用户数据库。
- 同名不同会话的旧商机仍只有显示名称，报告明确提示身份待核实，不擅自归属给其中一人。需要人工确认或后续基于证据绑定会话 ID。
- 未携带会话 ID 的文件导入维持旧去重方式；改昵称后的跨来源归并仍需核实。
- 规则不是完整语义理解。项目别名、隐含取消、多个项目混在同一句、附件中的完成证据仍需人工核实。联系人承诺默认回看 30 天，不能据此声称全部历史义务均已覆盖。
- 联系人页的筛选范围、机会判断和成交确认是三件不同的事；首次询价不算已谈妥商单。

## 验证

在公开引擎目录运行：

```bash
python3 -m unittest discover -s tests -p test_followup_regressions.py -v
python3 -m unittest discover -s tests -q
python3 scripts/build_release.py --out /tmp/wechat-hub-release-check
```

新增测试只用虚构联系人与项目，覆盖首次入站、取消、跨项目与跨轮次、否定与未来表达、多承诺、同名不同 ID、重复同步、旧哈希升级、FTS/链接引用和 Markdown/HTML 多项目展示。完整测试所需的可选依赖以测试输出为准；跳过的 SQLCipher 集成测试不代表已经通过真实解密验证。
