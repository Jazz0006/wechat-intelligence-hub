# 首次接入真实验收

这份清单用于验证 macOS 候选获取路线是否真的能让**新安装、尚无可读配置**的用户接通微信。仓库测试中的模拟授权和虚构加密库只能证明 Reader 的验证与配置流程，不能代替真实微信取钥验收。候选工具目前不是默认安装步骤。

## 测试前

1. 测试者只使用本人账号、本人电脑，先确认官方微信可以正常登录和查看聊天。已有 `ready` 配置的电脑只测试复用，不为凑首次成功而删除配置或重新获取。
2. 先运行 `access.sh onboard` 和 `access.sh diagnose --support-summary`，记录系统、芯片、微信版本及固定状态码；多账号时显式选定本人账号目录。不要把账号目录、原始日志、聊天、key、配置或截图发到 Issue。
3. 由测试者审阅固定提交、补丁和构建哈希。首次获取需要另行确认进程调试、官方微信可能退出、临时副本重签名及系统授权。安装 Skill 或运行诊断均不表示同意获取。
4. 本轮只尝试一次。先确认数据库读取权限和实际 LLDB 环境；缺依赖、权限不足、版本不适配或系统阻止副本启动时停止，不关闭 SIP、不修改官方微信签名、不循环重试。

## 通过标准

| 阶段 | 必须看到的证据 |
| --- | --- |
| 获取前 | `onboard` 指向单一本人账号；现有材料复用、依赖或权限问题已排除；候选二进制哈希与审阅结果一致。 |
| 获取后 | 获取器正常结束只是中间结果；`doctor` 和实际数据库读取须同时证明 `live_database_read_ok=true`。 |
| 覆盖 | 抽检本人指定的一条私聊、一条群聊和目标时间范围；明确记录本机未同步历史及未覆盖的数据库，不把部分覆盖说成全量。 |
| 恢复 | 测试者亲自确认官方微信重新打开、同一账号可正常查看聊天，且调试器、临时副本和授权窗口已结束；之后才完成恢复检查。 |
| 隐私 | 分享的支持材料仅为 `diagnose --support-summary` 白名单字段及人工概括，不含 key、原始日志、聊天或私有文件路径。 |

任一项失败都不记作首次接入成功。`provider_finished`、配置文件存在或“已请求重开微信”单独出现，均不足以通过。

## 失败分流

- `database_read_permission_denied`、`debugger_unavailable`：先修复实际执行进程的权限或工具链；获取器尚未运行，不重取 key。
- `other_wechat_install_running`、`official_wechat_scan_failed`、`official_wechat_process_unverified`：先核对进程和安装位置，不向不明实例发退出信号。
- `shadow_policy_blocked`、`pbkdf_shadow_*`：先确认官方微信是否恢复；系统策略拦截临时副本不能通过反复启动或关闭保护来掩盖。
- `account_salt_mismatch`、`key_verification_failed`：区分账号目录、派生参数和版本兼容，不能把未验证材料写成可用 key。
- `recovery_review_required=true`：即使数据库已可读，也必须等待用户事后确认官方微信正常，不能由先前的获取授权代替。

## 提升为默认路线的门槛

至少需要一台**此前没有可读配置**的支持版本 Mac 完成上表全部步骤，并有一次失败或取消后的微信恢复验收。Intel 与 Apple Silicon、不同 macOS/微信版本分别记录，未实测组合仍标为未知。Windows 获取是独立路线，不能沿用 Mac 的结果。达到门槛前保持 `candidate_not_default`，不要宣称“安装后自动找 key 已解决”。
